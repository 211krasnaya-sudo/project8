
# Catalog Project

Учебный проект: модели `Product` и `Category`, тесты `pytest`, покрытие кода, проверки качества
(flake8, black, isort, mypy).

Проект демонстрирует правильную структуру Python-пакета (`src/`) и работу с Poetry,
что удобно переносить в Flask/Django проекты.

## Структура проекта

- `src/models.py классы `Product`, `Category` с атрибутами `name`, `description`, `price`, `quantity`.
- `tests/test_models.pyтесты на инициализацию, подсчёт количества продуктов и категорий.
- `pyproject.toml зависимости и конфигурация Poetry.
- `.gitignor исключает виртуальное окружение, кэш тестов и отчёты покрытия.

## Функционал проекта

На текущем этапе (ветка `feature/magic-methods` и 'feature/inheritance-and-type-checks') реализованы следующие возможности:

### Модели данных
- **Product** — базовый класс товара с приватным атрибутом цены (`__price`) и геттером/сеттером. Сеттер проверяет корректность цены и запрашивает подтверждение при снижении цены.
- **Smartphone**, **LawnGrass** — наследники `Product` с дополнительными полями и переопределённым `__str__`.
- **Category** — категория товаров:
  - Приватный список товаров (`__products`).
  - Геттер `products`, возвращающий строковое представление всех товаров.
  - Класс-атрибуты `category_count` и `product_count` для учёта количества категорий и товаров.

### Магические методы
- `Product.__add__(other)` — сложение двух товаров одного класса возвращает суммарную стоимость (`total_cost`). Запрещено сложение объектов разных классов.
- `Category.__add__(other)` — сложение двух категорий возвращает суммарную стоимость всех товаров из обеих категорий.
- `Product.__str__()` и `Category.__str__()` — строковое представление объектов в удобном для чтения формате.

### Вспомогательные возможности
- `Product.total_cost()` — возвращает стоимость товара с учётом количества (`price * quantity`).
- `Category.total_quantity()` — общее количество товаров в категории.
- `Product.new_product(data, products_list)` — класс-метод для создания или обновления товара: если товар с таким именем уже есть в списке, увеличивает его количество и обновляет цену (если новая цена выше).

### Валидация и защита данных
- Проверка типов при добавлении товаров в категорию.
- Защита от некорректных значений (цена ≤ 0).
- Подтверждение при снижении цены через `input`.

## Реализованная функциональность (ветка feature/abc-and-mixin)

### Абстрактные классы и иерархия
- **`BaseProduct` (ABC)** — базовый абстрактный класс:
  - Содержит общую логику для всех продуктов (имя, описание, приватная цена, количество).
  - Защищает цену через геттер/сеттер (проверка на отрицательность и подтверждение при снижении).
  - Требует реализации методов `total_cost()` и `__str__()`.
  - Нельзя создать экземпляр напрямую (абстрактный класс).
- **`Orderable` (ABC)** — интерфейс для расчёта стоимости:
  - Абстрактный метод `calculate_total()`.
  - Реализован в классах `Product`, `Category` и `Order`.

### Миксин
- **`CreationLoggerMixin`** — автоматически выводит в консоль строку создания объекта при инициализации:
  ```text
  Product('Apple', 'Red', 1.2, 10)
  Smartphone('iPhone', 'Flagship', 1000, 2, ...)

## Реализованная функциональность (ветка feature/quantity-validation-and-avg-price-extra)
***Инициализации экземпляра класса
  - При инициализации экземпляра класса Product происходит обработка попытки 
  создания товара с нулевым количеством.
  - Если пользователь попытается создать продукт с нулевым количеством, выбрасывается ошибка 
ValueError с сообщением «Товар с нулевым количеством не может быть добавлен».
***Метод подсчета среднего ценника всех товаров
  - Реализован метод подсчета среднего ценника всех товаров в классе Category, который 
  складывает только цены (self.price) всех товаров категории и делит полученную сумму 
  на количество товаров в категории.
  - В методе обработан случай, когда в категории нет товаров. 
  В случае если такое происходит, возвращается ноль.
